## 0. Hallazgo crítico (RESUELTO 2026-09-16): el trabajo estaba disperso en ramas nunca fusionadas ni pusheadas

El equipo trabajó con **ramas apiladas** (`feature/mc-act-*`, cada una sale de la punta de la anterior). Periódicamente esa pila se fusionaba a `main` vía PR — pero dejó de pasar desde el 15/09 a la mañana. A partir de ahí, dos líneas de trabajo quedaron divergentes y ninguna de las dos estaba en GitHub (`git branch -a` no les mostraba `remotes/origin/...`, o sea: nunca se había hecho `git push`):

| Línea                              | Rama punta (local, sin push)                                                                                  | Contenido que main NO tiene                                                                                                                                                                                                  |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A — Comercios + Foros/Cursos**   | `feature/mc-act-ennr-caso-de-uso-inscribirsecurso-con-restricci-n-de-unicidad`                                | CRUD completo de `comercios`/`productos_comercio` (alta, catálogo, búsqueda pública), Módulo 8 completo (`cursos`, `inscripciones_curso`, `temas_foro`, `respuestas_foro`, moderación), `historiales_compartidos` (Módulo 6) |
| **B — Compatibilidad de adopción** | `feature/mc-act-mml7-estrategiamatchadopcion-con-strategy-intercambiable-reglas-sem-ntico-llm-` (rama actual) | Extensión de `PublicarFichaAdopcion` con atributos de compatibilidad, `cuestionarios_adoptante` (CRUD propio), `GenerarSugerenciasCompatibilidad` + Strategy `reglas`/`semántico`/`LLM`                                      |

**Estas dos líneas además son mutuamente independientes**: la rama B se creó desde `main` directamente, así que **no incluye nada de la línea A** (no tiene comercios ni foros-cursos). Si hoy se mergea B a `main` sin mergear A, comercios/foros/cursos/historiales-compartidos seguirían sin existir en producción.

**Estado actual (2026-09-16):** ambas líneas se fusionaron sobre `main` en la rama `chore/unificar-post-mvp-modulos-5-9`, sin descartar contenido de ninguna de las dos. Se verificó exhaustivamente con `git merge-base --is-ancestor <rama> HEAD` sobre **todas** las ramas locales del repositorio (no solo A y B) — la única que no resultó ya incluida fue `backup/5-tickets-combinados`, un snapshot viejo y estrictamente anterior, sin contenido único que rescatar. Los 4 conflictos de merge (`middleware.ts`, `docs/pruebas_testeos/INDEX.md`, `docs/DECISIONES.md`, un test de middleware) fueron todos aditivos — ambas líneas agregando entradas distintas a la misma lista — y se resolvieron conservando los dos lados; `contenedor-di.ts` se auto-mergeó sin conflicto.

Verificación completa corrida sobre la rama ya unificada (no sobre una rama parcial): `npm run typecheck` ✅ · `npm run lint` ✅ · `npm test` → **189 test suites / 1295 tests, todos verdes** · `npm run build` ✅ (compila para producción). Rama empujada a GitHub y **[PR #64](https://github.com/youngmariano99/PatitasEnAlerta/pull/64)** abierto contra `main`, con los 3 checks de CI (`lint-and-typecheck`, `test`, `build`) en verde.

**Pendiente, no bloqueante para el resto de este documento:** mergear el PR #64 a `main` (requiere aprobación humana por la regla de protección de rama).

En un ambiente de producción real (sin correr el seed de datos falsos), la tabla `roles` quedaría vacía y **nadie podría registrarse** (el alta de usuario depende de un `rol_id` válido). Se recomienda extraer esas 7 filas a su propia migración idempotente (`INSERT ... ON CONFLICT DO NOTHING`), separada de los datos de prueba aleatorios.
